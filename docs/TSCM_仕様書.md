# TSCM 会場事前手続き＋利用確認書 管理システム 仕様書

> GPCMボード（グレイドパーク専用・会場マスタ選択式）の`GPCM_仕様書.md`を土台に、TIMESHARINGシリーズ全会場向けに汎用化した版。
> 対象会場: TIMESHARINGシリーズ全会場（会場マスタは持たず、会場名・会場住所は案件ごとに自由入力）。

## 本書の目的

GPCMボードは「会場マスタ選択式（venueIdキーで会場ごとに選択肢・料金・ヒアリング項目を切替）」だったが、TSCMボードは対象会場が非常に多いため、会場を自由テキスト入力にし、オプション・料金は「全会場共通の最低限の標準項目」＋「会場ごとの自由記述オプション欄」で対応する汎用設計に変更した。柱は3点:
1. どこ（スプレッドシート）で管理するか
2. どのように保存されるか
3. 金額・項目の差異をスプレッドシートだけで編集できるか

## ① 全体構成

```
① スプレッドシート（5ファイル）        ② GAS（サーバー）                ③ 管理ボード（Web）
共通オプション・料金マスタ              オプション/会場/項目マスタ読込・   会場自由入力→標準/自由記述
よく使う会場                      →   保存/読込・利用確認書PDF生成  →   オプション入力→利用確認書出力
ヒアリング項目マスタ
共有事項テンプレ
TSCM_管理システム（案件データ）
```

## ② スプレッドシート構成

GPCMボードでは「会場マスタ」1ファイルに複数タブを持つ構成だったが、TSCMボードはGoogle Drive側のツール制約（1ファイル複数タブxlsxのアップロード変換が失敗した）により、**5つの独立したGoogleスプレッドシートファイル（各1シート）**として構成する。

| ファイル名 | 役割 | 列構成（1行目=見出し、2行目以降=データ） |
| --- | --- | --- |
| 共通オプション・料金マスタ | 標準オプション4項目の単価・計算方式 | コード／品目名／種別(manual・fixed・percentage)／単価(税別)／率(%)／単位／税表記(税別・税込)／表示順／備考 |
| よく使う会場 | 会場名+住所の再利用リスト | 会場名／会場住所／登録日時／登録者／備考 |
| ヒアリング項目マスタ | ①ヒアリングシートの項目定義（会場非依存・単一マスタ） | カテゴリ／項目名／種別(select/text/date/datetime/timerange/textarea)／選択肢(｜または|区切り)／初期値／補足メモ／会場依存フラグ(常時FALSE運用)／新規項目フラグ／ラクラクパック関連フラグ／ケータリング関連フラグ／お食事関連フラグ |
| 共有事項テンプレ | 立会スタッフ共有事項の既定文言（会場非依存・単一テンプレ） | テンプレ本文（2行目に本文） |
| TSCM_管理システム | 案件データの保存先 | caseId／保存日時／更新日時／作成者／最終更新者／会場名／会場住所／会社名／担当者／データ(JSON)／URL |

「共通オプション・料金マスタ」の初期データ:

| コード | 品目名 | 種別 | 単価(税別) | 率(%) | 単位 | 税表記 | 備考 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SPACE_EXT | スペース延長 | manual | (空欄) | — | 30分 | 税別 | 当日手入力 |
| SPACE_EXT_OT | 時間外スペース延長 | manual | (空欄) | — | 30分 | 税別 | 当日手入力 |
| TRASH | ゴミ処理料金 | fixed | 1350 | — | 袋 | 税別 | 会場で異なれば編集 |
| DRINK | 飲み放題人数追加・延長 | fixed | 3300 | — | 人・30分 | 税別 | 会場で異なれば編集 |
| MAINT | 維持管理費 | percentage | — | 5 | — | 税込 | 小計×5%で自動計算・単価直接入力不可 |

各スプレッドシートIDは`data/README.md`および各`.gs`ファイルの定数を参照。

## ③ 保存方法（案件データ）

1案件の内容をJSON化して`TSCM_管理システム`の1行に保存するイメージ:

```
{
  "caseId": "...",
  "venueName": "...", "venueAddress": "...",
  "company": "...", "client": "...",
  "blocks": [ { "id":1, "venueName":"...", "venueAddress":"...", "snap":{vals,memos},
                "standardFees":[...], "freeFees":[...], "layoutMemo":{...}, ... } ]
}
```

会場名・会場住所はブロックごとに保持されるため、同一案件内で複数会場・日程を比較検討できる（GPCMの「venueId」列は廃止し「会場住所」列を追加）。

## ④ 金額・項目の変更（スプレッドシート編集で反映）

| 変更したいこと | 編集するスプレッドシート |
| --- | --- |
| 標準オプションの単価変更 | 共通オプション・料金マスタ の単価(税別)列 |
| 維持管理費の率変更 | 共通オプション・料金マスタ の率(%)列（MAINT行） |
| ヒアリング項目の追加/削除/選択肢変更 | ヒアリング項目マスタ |
| よく使う会場の追加/編集 | よく使う会場（ボードの「＋この会場を登録」ボタンからも自動追記） |
| 共有事項テンプレ変更 | 共有事項テンプレ |

コードにはハードコードされた会場依存情報を持たず、スプレッドシート編集のみで反映できる（会場自体はマスタ化しないため「会場の追加」という概念がそもそも存在しない）。

## ⑦ GPCMボードからの主な設計変更点

- 会場をマスタ選択式（venueIdキー、14会場のプルダウン）から自由テキスト入力式に変更。会場マスタ・会場ごとの個別タブ（VENUE_TABS）は廃止。
- 会場ごとに異なっていた選択肢・追加料金・共有事項テンプレを、全会場共通の「標準オプション4項目」＋「自由記述オプション」＋「単一の共有事項テンプレ」に統合。
- ①ヒアリングシートの項目定義を、会場ごとの個別タブ（K〜U列）から単一のヒアリング項目マスタに統合（会場依存フラグは常時FALSE運用）。
- テキスト出力・取込を、GPCM固有の項目名に依存した専用フォーマット（本予約サマリー／旧バージョンTSV／罫線区切り「最新詳細書」形式）から、ヒアリング項目マスタの内容をそのまま網羅的に書き出す/読み戻す汎用タブ区切り形式に一本化（TSCMは新規システムのため、移行対象となる旧データが存在しないための簡略化）。
- 「④備品/使用エリア関係」の会場依存オプション（DEP_KEY・映像機器台数入力・6F共用備品等）・時間帯欄の連動表示（TR_PAIRS）は、会場マスタが存在しない汎用設計のため削除。ヒアリング項目マスタの「ラクラクパック関連／ケータリング関連／お食事関連」フラグは、タグ表示および最小限の条件表示（ケータリング区分に応じた表示切替）として実装。
